AI投資情報OS 全体構成図

売買助言ではなく、対象銘柄に関する事実、証拠、変化、仮説への影響、不確実性を整理するための全体像です。

凡例

色で役割を分けています。LLM Agentは考える係、取得モジュールは取ってくる係、Dataは保存される正本、UI/Outputはユーザーが触る場所です。

LLM Agent 非LLM取得モジュール Data / 正本 UI / Output 内部監査 売買助言はしない

全体構成

User
ユーザー 朝に音声で把握し、引け後に情報を読む。疑問はChat Judgeへ聞く。
人間メモ 判断、気づき、架空ポジション、後日検証の記録。
Sources
J-Quants Light 株価、出来高、売買代金、財務、決算予定。
EDINET API 大量保有報告書、有報、臨時報告書。
IR / News 企業IR、公開ニュース、イベント情報。
Collect / Format
情報収集オーケストレーター 取得モジュールを実行し、取得失敗や更新状況をHealthへ記録。
証拠化Agent 素材を証拠カードへ成形。要約、重要数値、4軸評価、方向ラベルを付ける。
Data Core
Evidence DB 全Agentが読む共通土台。事実、証拠、評価、人間メモを保存。
Agent出力JSON 各Agentの主張、claim_strength、根拠、未確認情報を保存。
Report Judge JSON 方向スコア、confidence、情報状態、仮説影響、不確実性を保存。
Agents / Judges
探索設計Agent 日次、週次、中期レビューなど、目的と期間に応じて調査論点を設計。
分析Agent群 強気、弱気、反証、織り込みの視点で、論理的に言える範囲だけを出す。
Report Judge 定型レポートの最終情報整理者。売買行動は提案しない。
Chat Judge ユーザー質問の司令塔。Quick、Context、Agent、Researchを使い分ける。
UI / Outputs
朝レポート / 音声 起床後に耳で動向を把握する短時間ブリーフ。
引け後レポート その日の事実、重要証拠、方向感、未確認情報を整理。
Evidence UI 1銘柄専用の高密度ニュースサイト。記事からAI質問も可能。
Dashboard / Review / Health 全体状態、週次振り返り、内部チェックを表示。

定時レポート生成の流れ

1. 目的を決める 朝レポート、引け後レポート、週次レビューなど。
2. 探索設計 対象期間と目的に応じて、確認する論点を決める。
3. 情報取得 J-Quants、EDINET、IR、Newsを取得モジュールが収集。
4. 証拠化 証拠化Agentが証拠カードに変換し、Evidence DBへ保存。
5. 視点別分析 強気、弱気、反証、織り込みAgentがclaim_strength付きで出力。
6. Report Judge 情報状態、仮説影響、方向スコア、confidenceを整理。
7. 出力 Markdown、音声用Markdown、HTML、Evidence UIへ展開。

Agent同士のつながり

探索設計Agent

LLM Agent
  • 入力: 目的、期間、対象銘柄、前回判定、不足情報
  • 出力: 調査論点、優先情報源、終了条件
  • 次へ: 情報収集オーケストレーター

証拠化Agent

LLM Agent
  • 入力: 取得素材
  • 出力: Evidenceカード
  • 次へ: Evidence DB、分析Agent群

分析Agent群

LLM Agent
  • 強気: 仮説を補強する事実
  • 弱気: 仮説を弱める事実
  • 反証: 仮説を壊し得る事実
  • 織り込み: 価格反映・過熱

Report Judge

LLM Agent
  • 入力: Evidence DB、Agent出力、中期仮説
  • 出力: 情報状態、仮説影響、方向スコア
  • 売買行動は提案しない

ユーザーとAgentのつながり

定時で受け取る

接点 主な裏側 ユーザーが得るもの
朝レポート 探索設計、取得、証拠化、軽い差分整理 起床後に耳で重要動向を把握
引け後レポート 全Agent、Report Judge その日の事実、方向感、不確実性
週次レビュー 過去Evidence、Judgeログ、Review集計 中期仮説の変化と見落とし

質問して使う

入口 Chat Judge Mode 動く範囲
記事のAI質問 Quick 選択中Evidenceと関連Evidenceのみ。新Agentは呼ばない。
銘柄について質問 Context 既存Evidence、既存Agentログ、Report Judge出力。
視点を指定 Agent 必要な特定Agentだけ呼ぶ。
新テーマ調査 Research 探索、取得、証拠化、複数Agentを動員。

Report Judgeが出すもの

information_status

情報状態
  • 強気材料優勢
  • 弱気材料優勢
  • 材料拮抗
  • 情報不足
  • 大きな変化なし

hypothesis_impact

仮説への影響
  • 補強
  • やや補強
  • 中立
  • やや悪化
  • 悪化
  • 判定不能

uncertainty

不確実性
  • 未確認情報
  • 情報品質
  • 直接性不足
  • 数値不足

view_change_conditions

見方が変わる条件
  • 行動指示ではない
  • 情報解釈が変わる条件
  • 仮説影響が変わる条件

このOSの原則

売買助言をしない

保有継続、追加、撤退などの行動提案は原則出さない。提供するのは事実と根拠。

全Agentは同じ証拠を見る

Evidence DBを共通土台にし、伝言ゲームや根拠不明の主張を避ける。

ログは反省のため

ポジションや架空ポジションは助言のためではなく、判断ログと後日検証のために使う。
