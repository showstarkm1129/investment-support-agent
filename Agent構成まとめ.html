ここまで決めたMVP設計を、Agentの役割、入力、出力、つながりが分かるように整理した確認用ページです。

全体フロー

Input

対象銘柄・仮説・ポジション

  • 日本株から1銘柄を選択
  • 2週間から3か月の中期スイング
  • 実ポジション / 仮想ポジション / 監視

探索設計Agent

  • 今日見る論点を決める

証拠化Agent

  • 4軸評価と仮ラベル付け
  • 証拠DBへ保存

  • 強気Agent

情報収集まわりの分担

ここは「考えるAgent」と「決まった場所から取ってくるプログラム」を分けて扱います。

LLM負荷を下げる設計

情報収集オーケストレーター

探索設計Agentの指示を受け、どの取得モジュールをいつ動かすかを管理する非LLM処理。

  • 対象銘柄と日付を渡す
  • 取得順序を管理する
  • 成功/失敗をHealthへ記録する

J-Quants取得モジュール

J-Quants API Lightから、株価、出来高、売買代金、財務、決算予定などを取得する。

  • 価格と出来高の更新
  • 財務・決算予定の取得
  • 定量データの素材化

EDINET取得モジュール

EDINET APIから、有報、臨時報告書、大量保有報告書などの公的開示を取得する。

  • 提出書類一覧の確認
  • 書類IDとメタ情報の取得
  • 必要に応じてPDF/XBRL/CSV取得

IR / News取得モジュール

企業IRページ、公開ニュース、イベント情報を確認し、新しい素材を集める。

  • IR資料やPDFリンクを確認
  • 公開ニュースを検索
  • タイトル、URL、短い本文候補を取得

取得モジュールは投資判断をしません。取ってきた素材を、証拠化Agentが固定フォーマットの証拠カードに整えます。

つながりマインドマップ

Core 証拠DB 全Agentが同じ根拠カードを読む共通土台。
Plan 探索設計Agent 今日の論点、不足情報、追加調査タスクを決める。
Non LLM 情報収集オーケストレーター J-Quants、EDINET、IR、News取得を実行管理する。
Format 証拠化Agent 素材を要約し、4軸評価と方向ラベルを付ける。
Bull 強気Agent 中期仮説を補強する材料の強さを出す。
Bear 弱気Agent 悪材料、過熱、ポジションリスクを検証する。
反証 反証Agent 仮説が間違っている兆候を探す。
Pricing 織り込みAgent 材料がすでに価格に反映されたかを見る。
Judge 裁判官Agent Agent主張を比較し、方向スコアと最終判定を出す。

Agent一覧

探索設計Agent

設計

今日調べるべき論点を決める。裁判官Agentから追加調査依頼が出た場合も、取得先と調査方針を組み立てる。

  • 入力: 仮説、対象銘柄、前回判定、不足情報
  • 出力: 調査タスク、取得対象、優先順位

証拠化Agent

成形

取得モジュールが集めた素材を、固定フォーマットの証拠カードに変換する。最終投資判断はしない。

  • 入力: 取得素材、保存ポリシー、対象銘柄
  • 出力: evidence_id付き証拠カード
  • 評価: 4軸評価、direction_hint、重複処理

強気Agent

Bull

証拠DBから、中期仮説を強める材料を探す。無理に強気化せず、論理的に言える強さだけを出す。

  • 入力: 証拠DB
  • 出力: 強気結論、claim_strength、根拠ID

弱気Agent

Bear

リスク、悪材料、過熱、ポジションを取る危険を検証する。弱気材料が弱い日は、重みの低い主張として出す。

  • 入力: 証拠DB
  • 出力: 弱気結論、claim_strength、根拠ID

反証Agent

反証

「この投資仮説が間違っているなら何が見えるか」を検証する。仮説を壊す兆候を探す。

  • 入力: 証拠DB、中期仮説
  • 出力: 反証候補、claim_strength、判定変更条件

織り込みAgent

Pricing

良い材料がすでに株価や需給に反映されていないかを見る。短期追撃リスクもここで扱う。

  • 入力: 証拠DB、価格/出来高
  • 出力: 織り込み判定、過熱判定、claim_strength

裁判官Agentの役割

見るもの

  • 証拠DB
  • 4つのAgent出力
  • 中期投資仮説
  • ポジション情報
  • 前回の裁判官判定

しないこと

  • 新しい外部情報を勝手に検索しない
  • 証拠DBにない情報を根拠にしない
  • 両論併記だけで中立に逃げない
  • Agentの論理飛躍をそのまま採用しない

再調査ループ

1. 証拠DB 証拠化Agentが整えた根拠カードを保存する。
2. 各Agent 与えられた視点で論理的に言える強さを出す。
3. 裁判官 証拠と主張を比較し、不足情報を確認する。
4. 不足あり missing_information と next_research_tasks を出す。
5. 追加調査 探索設計Agentと取得モジュールで最大1回だけ実行する。
6. 再評価 証拠DBを更新し、各Agentを再実行する。
7. 最終判定 弱気から強気までの判定と方向スコアを出す。

設計ルール

Agentは論者ではなく検証者

自分の視点に沿って、証拠から論理的に言える範囲だけを主張する。証拠が弱い場合は弱い主張として出す。

claim_strengthは0から100

各Agent視点での主張の強さ。最終的な投資方向ではない。

direction_scoreは裁判官だけ

最終方向スコアは-100から+100。弱気、中立、保留、強気を裁判官Agentが決める。
